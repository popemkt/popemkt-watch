# Changelog

## Unreleased

- Toolchain to latest (the held majors): **AGP 8.13.2 → 9.2.1, Gradle 8.13 → 9.5.1, Kotlin 2.0.21 → 2.4.0, compileSdk 36 → 37**, plus the libraries that were gated on them — core-ktx 1.16 → 1.19, activity-compose 1.10.1 → 1.13.0, coroutines 1.10.2 → 1.11.0, konsist 0.16.1 → 0.17.3, compose-BOM 2024.12 → 2026.05.01. **AGP 9 ships built-in Kotlin**, so the standalone `org.jetbrains.kotlin.android` plugin was removed from all three build files (it now errors if applied) and the JVM target moved from `android.kotlinOptions` to the project-level `kotlin { compilerOptions { jvmTarget } }`. Baseline-profile tooling pinned to `1.5.0-alpha06` — the only line that supports AGP 9 (dev-only `generateBaselineProfile`, never in the app runtime; `TODO NGH` to drop to stable). `assembleRelease`, `test`, and `detekt` all green under Gradle 9. Specs: `01-architecture.md` § Toolchain + baseline-profile note.

- Tile matches the app's Material 3 look. Rewrote `AgendaTileRenderer` from classic `protolayout-material` (`PrimaryLayout`/`CompactChip`/`Text.Builder`) to **`protolayout-material3`** (`materialScope { primaryLayout(titleSlot/mainSlot/bottomSlot) }`, stable as of 1.4.0): caption in the title slot, the tappable event `titleCard` + `‹`/`›` `textButton`s in the main slot, and **`Open` as a `textEdgeButton`** that hugs the round bottom edge — the tile's native answer to "fit the roundness" (a tile is a single static snapshot with no scrolling list, so the agenda's `TransformingLazyColumn` morph itself does not apply; the edge button is the closest equivalent). Colors/typography now come from the M3 scope's `ColorScheme` (dynamic Material-You theming) instead of hand-picked argb. Tile behavior is unchanged — same read-only glance, `‹`/`›` cursor, and card-tap state cycle through `ReminderCoordinator`. Supersedes the earlier "classic protolayout-material (material3 pre-stable)" decision in `specs/01-architecture.md` § Tile surface.

- Dependency freshening (the AGP-8 / Kotlin-2.0-safe tier): detekt 1.23.7 → 1.23.8, androidx core-ktx 1.15.0 → 1.16.0, activity-compose 1.9.3 → 1.10.1, wear 1.3.0 → 1.4.0, wear-tiles 1.4.0 → 1.6.0, protolayout 1.2.1 → 1.4.0, datastore 1.1.1 → 1.2.1, work 2.10.0 → 2.11.2, coroutines 1.9.0 → 1.10.2, benchmark/baseline-profile 1.3.3 → 1.4.1, test-ext-junit 1.2.1 → 1.3.0. Held back deliberately because their newest releases now require **Kotlin 2.1+ or AGP 9.1 / compileSdk 37**: core-ktx 1.19, activity-compose 1.13, coroutines 1.11, konsist 0.17, and compose-BOM 2026.x. Those land with the AGP-9 + Kotlin-2.4 toolchain bump, tracked as a separate change so the majors fail in isolation rather than mixed into library churn.

- Agenda + Settings now **fit the round screen**: migrated the app UI from Wear Compose Material 2.5 (`ScalingLazyColumn` + `Chip` + `Scaffold`/`Vignette`) to **Material 3** (`AppScaffold`/`ScreenScaffold` + `TransformingLazyColumn`). Rows scale and morph to the display's curve at the top/bottom edges — the same first-class component the 2024+ Gemini/Google Calendar Wear surfaces use, not a hand-rolled effect. Active event rows are `FilledTonalButton` pills; Done rows recede to a backgroundless `ChildButton`; steppers are `FilledTonalIconButton`. Behavior is unchanged — same day grouping, state glyphs, one-tap cycle, and the precomputed `buildSections` render model. Recorded in `specs/00-product.md` § Agenda and `specs/01-architecture.md` § Toolchain + decision record. **Toolchain floor raised** by the migration: Wear Compose 1.4.0 → **1.6.2** (+ new `compose-material3`), which requires `compileSdk 35 → 36`, which requires AGP 8.7.3 → **8.13.2** and Gradle 8.11.1 → **8.13**. AGP 9.x and Kotlin 2.4.x are deliberately held for a separate change (independent majors; keeps this migration bisectable).

- Fixed: tapping a missed event (or any event 6h–2d old / >48h out) in the agenda — or the tile — appeared to do nothing. `ReminderCoordinator.refresh()` pruned reminder state to the **firing** window (`now−6h … now+48h`), but the agenda shows a far wider window (`now−2d … now+8d`). Marking such a row done/snoozed wrote the state, then the same refresh's prune immediately deleted it (its instance wasn't in the firing window), so the row reverted on redraw. Prune now retains the **agenda/display window's** keys (`actionableKeys`); the firing scan (`firingInstances`) is unchanged, so due-detection and the single-alarm schedule are byte-for-byte identical (`ReminderPlanner` is unaffected — its output never depended on the pruned-away states). Recorded in `specs/01-architecture.md` § Data flow. No unit test added: the coordinator's collaborators (notifier, alarm scheduler, state store) are Android-concrete with no fake seam, and the pure `ReminderPlanner` it delegates to is already covered and provably unchanged here.

- Watch tile — tap to change state: the event card is now a single large touch target that cycles the reminder state (upcoming → done → snooze → reset), exact parity with an agenda row, naming the next tap's outcome on the card (`tap: done` / `done → snooze` / `snoozed → reset`). Routes through the same `ReminderCoordinator` actions the agenda and notification buttons use — a glance still schedules nothing; the tap re-arms the single existing alarm (user-initiated, no new wakeup). Layout redesigned around it: position/time caption, the tappable card, a `‹ ›` nav row, and the `Open` chip — every action a big thumb target, no Done/Snooze buttons crowding the round screen. (Tiles cannot scroll — the `‹ ›` cycle is the platform-level substitute for the app's scroll list.)

- Watch tile (P2): a glanceable `tile/AgendaTileService` showing one upcoming event at a time — day label, title, start time, `N / M` position, and the agenda's state glyph (`✓`/`Zz`). `‹`/`›` buttons cycle through the forward events in place; an `Open` chip launches the app; empty/no-permission states tap through to grant. **Read-only and wakeup-free**: renders from the calendar mirror + persisted reminder state, never calls `ReminderCoordinator.refresh()`, schedules nothing — zero added to the wakeup budget (battery rule). Cursor persists across glances (`TileCursorStore` + ProtoLayout `lastClickableId`); clamps when the list shifts. Classic `protolayout-material` (material3 still pre-stable); futures via `ResolvableFuture`. Done/Snooze deliberately stay in the app (decision record in `specs/01-architecture.md` § Tile surface). `AgendaEntry` moved `ui` → `domain` so both presentation surfaces share it without coupling; new `tile` layer added to the Konsist fence map.

- Performance (P0): release builds are now R8-minified and sideloadable (debug-key-signed for testing) so on-watch perf is judged on a non-`debuggable` build — the real cause of the scroll jank. Added baseline-profile infrastructure: new `:apps:watchcal-baselineprofile` (`com.android.test`) producer module with a startup+scroll journey, `androidx.baselineprofile` plugin + `androidx.profileinstaller`, and a `generateBaselineProfile` entrypoint (runs on a connected device/emulator) for JIT-free startup and scroll. Roadmap recorded in `specs/03-roadmap.md`.

- Missed events no longer blast on cold start: a start-trigger only rings within a 10 min "missed grace" of the event start (`ReminderDefaults.MISSED_GRACE_MILLIS`); older start-triggers are *missed* — shown in the agenda (markable done / snoozable) but never auto-notified. Fixes the fresh-install case where every already-started event of the day fired a notification at once. Snooze-returns are unaffected (always ring when due).
- Agenda now shows the whole calendar mirror, past included (`now − AGENDA_LOOKBACK_MILLIS` … `now + AGENDA_FORWARD_MILLIS`), decoupled from the narrower firing window (`SCHEDULING_FORWARD_MILLIS`, formerly `AGENDA_WINDOW_MILLIS`). Earlier-today/yesterday and missed events are visible and actionable. New day headers: `Yesterday`, weekday, and `MMM d` dates; missed rows get a `!` glyph.
- Settings moved to a `⚙` gear chip pinned at the top of the agenda (under the clock) — reachable without scrolling.
- Scroll jank fixed: agenda grouping + per-row string formatting is precomputed once per data change (`remember(entries)` → `buildSections`) instead of allocating `Calendar`/`DateFormat`/`groupBy` on every scroll frame.

- Gentler, longer alert tone: `watchcal_alarm.wav` regenerated as a soft ~10 s rising-arpeggio bell chime (pure sines, soft attack, long decay, normalised below clipping) replacing the harsh dual-tone beep. Set as the channel sound on the `USAGE_NOTIFICATION` stream (channel `reminders_v5`; `USAGE_ALARM` had suppressed the whole alert on the Xiaomi Watch 5). Attention rides duration, not harshness; loops under `FLAG_INSISTENT` until acted.

- Agenda redesign: Wear `Scaffold` (curved clock + vignette) over a `ScalingLazyColumn`, rows grouped under `Today`/`Tomorrow`/weekday headers, a leading state glyph (`○`/`Zz`/`✓`) with muted+struck styling for done rows, a styled empty state, the full-screen-intent grant demoted to a single `⚠` warning chip, and Settings reached via a `⚙` compact chip at the foot. The one-tap state cycle is kept but its secondary label now names the next tap's outcome (`tap: done` / `done → snooze` / `snoozed → reset`). No icon-font dependency added — text glyphs only.
- Settings: sound test reduced to the single one-tap "Test sound" the spec promises; the five-path diagnostic cycler (a dev affordance that had leaked into the release surface) is removed. Settings now also has the curved clock + header.

- Adaptive launcher icon: replaced the stock `@android:drawable/ic_menu_my_calendar` (a flat menu glyph with no background, hence the "barebone, no circle" look) with a proper adaptive icon — a calendar page + clock-face foreground over a teal full-bleed background that Wear masks to a circle. Foreground/background/monochrome layers in `res/mipmap-anydpi-v26`; minSdk 30 means no legacy PNG fallback is needed.

- Sound investigation closed: the Xiaomi Watch 5's Android audio framework exposes no speaker output to apps (all playback APIs fail with ENODEV; see `specs/learnings.md`). Alerts are vibration-first on this device. Settings "Test:" chip cycles five playback variants for diagnosing future devices.

- Alarm-style full-screen alert: a due reminder lights the screen, takes it over (title + Snooze/Done), and rings + vibrates on the alarm stream until acted on; ring bounded at 60 s, then auto-snoozes. Any exit other than Done (swipe back, timeout) is a snooze. Heads-up fallback when the watch is in use.
- Configurable snooze interval: minutes + seconds steppers in a new in-app Settings screen (default 10 min, clamped 10 s – 60 min, stored in `ReminderSettingsStore` DataStore, read at snooze time).
- Agenda tap now toggles: done rows can be undone — undo re-enters the nag loop as snoozed for one interval.
- Full-screen alert grant flow: API 34+ denies full-screen intents by default for sideloaded apps; agenda shows an "Allow full-screen alerts" chip deep-linking to the system grant page until granted (degrades to heads-up meanwhile).
- Bundled loud alarm tone (`res/raw/watchcal_alarm.wav`, generated by `scripts/generate-alarm-tone.py`) replaces the device default ringtone — urgent dual-tone beeps at full player volume on the alarm stream.
- Channel v3: reverted to default notification sound — a custom alarm-stream sound suppressed the entire alert (no sound, no vibration) on Xiaomi Watch 5; kept the vibration pattern and `FLAG_INSISTENT`. Bundled tone retained behind a `TODO NGH:` for on-device bisecting.
- Agenda tap now cycles three states: upcoming → done → snoozed (undo) → upcoming (reset; fires at start again or immediately if started).
- Ring moved from the full-screen activity to the notification itself (`FLAG_INSISTENT` + channel sound on new `reminders_alarm` channel): the loop now sounds even when the system downgrades the takeover to heads-up (ambient/AOD, charging). `AlarmRinger` deleted; `AlarmActivity` is presentation-only.
- `specs/learnings.md`: new home for environment/device facts (Xiaomi Watch 5 adb + FSI appop quirks, mirror lag, build-machine JDK).

- Bootstrap repo as spec-as-source monorepo (`apps/`, future `libs/`): `AGENTS.md` harness, `specs/` (functional + technical + code-unit cohesion contract + rules index), adapted minimally from the Draiver harness.
- WatchCal MVP (`apps/watchcal`): standalone Wear OS app reading the OS calendar mirror (`WearableCalendarContract`), snooze-until-done reminder loop (swipe-away = snooze, only Done dismisses), single re-armed exact alarm, hourly WorkManager safety net, Preferences DataStore state, Compose for Wear OS 48h agenda.
- Cohesion harness wired: Konsist L1 fences (test-enforced), detekt L2 sensors (warn-only, `config/detekt/detekt.yml`), L3 rubric in spec.
